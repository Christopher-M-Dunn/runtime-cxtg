| `CXTG_QEMU_Action_Plan.md`     |         | **(4)** High-level project guide defining the implementation phases, to aid in writing subphase specs and plans. Before writing a subphase's spec, check **(5)** for any `deferred`/`pending`/`?`-phase(s) ADRs affecting it or a parent phase, and resolve them first — see `CLAUDE.md` for the gate-check rules (not yet its own diagram). | `ADR_log.md`                   | **new** | **(5)** Single index of every Decision, Bug, and Note — one global, sequential ADR number across all three; nothing is deleted, an entry just changes status. Replaces `todo.md`, `bugs.md`, `todo_archive.md`, and `Implementation_Choices.md` outright: **(4)** is stale whenever a `deferred`/`pending`/`?` Decision affects a phase not yet started. **Decisions** are dense fact only (CSR addresses, WARL behavior, encodings — no rationale): `deferred` (undecided) → `pending` (decided, booked to a phase) → `in progress` (folded into an already-running phase) → `incorporated` (written into **(4)**/the code), or `superseded` (replaced by a later ADR, which it points to) at any point. **Bugs** are `open`/`closed` — behavioral only, closes on verified-fixed, never touches **(4)**. **Notes** are `active`/`retired` guidance to a phase's implementer, or (`phase(s) = all`) a project-wide convention — also never touches **(4)**. A self-contained piece of any entry that needs its own tracking spawns a child ADR, cited by number from the parent. |
